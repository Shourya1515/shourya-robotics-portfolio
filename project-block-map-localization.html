Block-Map LiDAR Localization

  • Autonomous Robotics · Northeastern
  • Mar – Apr 2025 · solo
  • Python
  • Open3D
  • Branch-and-bound + ICP

A Python / Open3D reimplementation of a block-map localization method from an ICRA 2024 paper. Instead of matching every LiDAR scan against one large global map, the map is split into overlapping block maps; the robot is localized coarsely with a branch-and-bound search (BBS), then its pose is refined and tracked with ICP.

Why Block Maps

Matching each LiDAR scan against a single global map gets expensive as the environment grows. Splitting the map into smaller, overlapping block maps bounds the search to the region the robot is in, while the overlap keeps enough context for reliable matching when the robot crosses from one block into the next.

Pipeline

  1. Build block maps: accumulate registered scans into a block until the robot has travelled farther than the block size, then start a new one; index the block centroids in a KD-tree.
  2. Select the active block from the centroid nearest to the current position.
  3. Coarse initialization: branch-and-bound search over a multi-resolution map pyramid.
  4. Tracking: ICP refinement (Open3D) against the active block, with motion prediction and a sliding window of keyframes that is trimmed when switching blocks.

Results

  • On a ~600 m simulated trajectory, the tracked pose stayed under about 0.2 m error for most of the run.
  • The five block-map switches each caused a pose jump under 0.05 m.
  • The estimate drifted in Y over time; the original paper reports about 0.1 m.

Scope

A study reimplementation to understand the method: it runs on LiDAR point clouds with a synthetic trajectory and poses rather than a ground-truth dataset, with no ROS integration or hardware.
